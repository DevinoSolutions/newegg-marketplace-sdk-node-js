# Publishing

How to release `@devino/newegg-marketplace-sdk` and `@devino/newegg-marketplace-mcp` to npm,
including how to rename the placeholder `@devino` scope to your own, the versioning policy,
and the pre-publish verification gates.

Both packages already declare `"publishConfig": { "access": "public" }`, so scoped public
publication works out of the box.

---

## Rename the `@devino` scope

`@devino` is a **placeholder scope, chosen to be trivially find-and-replaceable.** Before
publishing under your own npm organization, replace `@devino/` with `@your-scope/`
everywhere it appears in tracked files.

### Files that reference the scope

| File                               | Reference                                                                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `packages/sdk/package.json`        | `"name": "@devino/newegg-marketplace-sdk"`                                                                  |
| `packages/mcp-server/package.json` | `"name": "@devino/newegg-marketplace-mcp"` **and** the `dependencies["@devino/newegg-marketplace-sdk"]` key |
| `package.json` (root)              | `build` and `pack:dry` scripts select `-w @devino/newegg-marketplace-sdk -w @devino/newegg-marketplace-mcp` |
| `scripts/verify-exports.mjs`       | the expected package `name`s it checks                                                                      |
| `packages/mcp-server/src/**`       | source imports of the SDK by package name (once implemented)                                                |
| `README.md` and `docs/**`          | code snippets and prose that import the packages                                                            |
| `package-lock.json`                | regenerated by `npm install` — do not hand-edit                                                             |

The `docs/adr/**` and `docs/research/**` files also mention `@devino` as historical/design
references; update them only if you want the record to reflect the new scope.

### Procedure

1. Replace the string `@devino/` with `@your-scope/` across the working tree (excluding
   `node_modules`). For example:

   ```bash
   # dry run — list every occurrence first
   grep -rl --exclude-dir=node_modules '@devino/' .
   ```

   Then apply the replacement with your editor's project-wide replace, or a scripted pass,
   over exactly those files.

2. Regenerate the lockfile so workspace links resolve under the new names:

   ```bash
   npm install
   ```

3. Re-run the verification gates below; `npm run verify:exports` confirms the renamed
   packages still expose their expected entry points.

> Keep both package names on the same scope — the MCP server depends on the SDK by name, so a
> half-renamed pair will not resolve.

## Versioning policy

- **Semantic versioning.** Both packages start at `0.1.0`.
- The SDK's **public API contract** is `docs/research/sdk-public-api.md`. A breaking change
  to that surface is a **major** bump; additive, backward-compatible changes are **minor**;
  fixes are **patch**. During `0.x`, treat minor bumps as potentially breaking per the semver
  `0.y.z` convention, and say so in release notes.
- The MCP server depends on the SDK via a caret range (`"@devino/newegg-marketplace-sdk":
"^0.1.0"`). Bump that range whenever you rely on a newly added SDK feature, and prefer
  releasing the two packages **in lockstep** so a given MCP version has a known-good SDK.
- Node engine support is `>=22.12.0`; CI validates on Node 22.x and 24.x
  (`.github/workflows/ci.yml`). Dropping a Node line is a breaking change.

## Pre-publish verification

Run the full gate from a clean checkout. These are the same checks CI runs, plus the
publish-specific `pack:dry`:

```bash
npm ci                    # clean, locked install
npm run check:secrets     # no credentials committed (see below)
npm run build             # tsc build of both packages
npm run typecheck         # tsc --noEmit across workspaces
npm run lint              # eslint
npm run format:check      # prettier --check
npm run test:coverage     # vitest with coverage (no credentials needed)
npm run verify:exports    # built entry points expose expected exports
npm run pack:dry          # inspect the tarball file lists
```

- **`check:secrets`** (`scripts/check-secrets.mjs`) fails the release if `.gitignore` does
  not exclude `.env`, if any value from a local `.env` appears in a tracked file, or if a
  credential-shaped value sits next to an `Authorization`/`SecretKey`/`NEWEGG_API_KEY`
  marker (Newegg's documented dummy examples are allowlisted). Exit code 1 on any finding.
- **`verify:exports`** (`scripts/verify-exports.mjs`) imports each built package and checks
  that its expected named exports are present and that every `exports` target file — the
  root entry and the SDK's `./testing` subpath — exists on disk. Run it **after** `build`.

### Review the `pack:dry` output

`npm run pack:dry` runs `npm pack --dry-run` for both packages. Confirm the tarball contents
match each package's `files` allowlist (`["dist", "README.md"]`) — you should see the built
`dist/` and the README, and **must not** see `src/`, tests, `.env`, tsconfig, or coverage.
Anything unexpected means a stray file would ship to npm.

## Publish

Build first, then publish the **SDK before the MCP server** (the MCP package depends on the
SDK being resolvable on the registry):

```bash
npm run build

npm publish --access public -w @devino/newegg-marketplace-sdk
npm publish --access public -w @devino/newegg-marketplace-mcp
```

`--access public` is explicit even though `publishConfig.access` already sets it — harmless
and clear. Add npm **provenance** when publishing from trusted CI (npm ≥ 9.5 with OIDC),
which attaches a verifiable build attestation:

```bash
npm publish --provenance --access public -w @devino/newegg-marketplace-sdk
npm publish --provenance --access public -w @devino/newegg-marketplace-mcp
```

`--provenance` requires a supported CI environment (e.g. GitHub Actions with `id-token:
write`); it will fail on a local machine.

## Tag and release notes

After a successful publish:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Create a GitHub release for the tag with notes that cover:

- **API changes** relative to `docs/research/sdk-public-api.md` (new/changed/removed surface),
  flagged as major/minor/patch.
- **Platform or wire-contract corrections** (e.g. a resolved assumption from
  `docs/platform-differences.md`).
- **MCP tool/resource changes** and any change to default safety posture
  (`NEWEGG_MCP_ALLOW_WRITES`, TTLs, guard limits).
- **Known limitations** carried forward (no price updates, feed date filters, unresolved
  assumptions).

## Release checklist

- [ ] Clean working tree, on `main`, CI green.
- [ ] Version bumped in `packages/sdk/package.json` and `packages/mcp-server/package.json`
      (and the SDK dependency range in the MCP package if needed).
- [ ] `npm ci`
- [ ] `npm run check:secrets`
- [ ] `npm run build`
- [ ] `npm run typecheck`
- [ ] `npm run lint && npm run format:check`
- [ ] `npm run test:coverage`
- [ ] `npm run verify:exports`
- [ ] `npm run pack:dry` — file lists reviewed (`dist` + `README.md` only).
- [ ] `npm publish` SDK, then MCP (`--access public`, `--provenance` in CI).
- [ ] `git tag` + push + GitHub release notes.
- [ ] Smoke test: `npx -y @your-scope/newegg-marketplace-mcp` (stdio boots) and
      `npm i @your-scope/newegg-marketplace-sdk` in a scratch project (types resolve).
